# Curriculum Skeleton: Content Areas for AI / Software Development

- **Author:** Charles, with additions from Chris
- **Date:** 2026-10-20
- **Type:** program structure
- **Maturity:** sketch

## The idea

Organize the program around the parts of building production software that AI-assisted
("vibe") coding does not provide on its own:

| Area | Notes |
| --- | --- |
| Systems (not low-level) | Full stack, UX, dev flow and documentation (Chris) |
| Data | Flow, processing, storage |
| UI/UX | |
| Process | Agile / scrum |
| Testing / Verification / QA | |
| DevOps | Deploying and running what you build |

## Why it matters

Students can now produce impressive-looking apps quickly. In the 2026-10-19 demos, the gaps were
in what surrounds the code: where state lives, usability, finishing details, and testing. See
[observed-gaps-from-student-demos.md](observed-gaps-from-student-demos.md).

## How it might work

Undecided. Packaging depends on the scope question in
[open-questions.md](../open-questions.md):

- **Certificate or minor:** roughly one course per area (~6 courses)
- **Major:** these areas plus additional courses, such as business start-ups,
  community-driven development, or a labor course; or a partnered business minor
  through Milgard

## Open questions / risks

- Which of these areas are already covered by existing CS / CSS courses?
- Is "Systems" one course or several?
