## Course Information

- **Course:** TCSS 461 Advanced Software Engineering, 5 credits
- **Prerequisite:** TCSS 360
- **Format:** studio course. Students build throughout the quarter, ending in a team capstone
  project.

### Catalog Description

Analyzes system re-engineering, domain-specific languages, generative development, system design,
and software architecture. Also covers how to handle legacy systems, utilize model-driven and
automated approaches to code generation, and understand low- to high-level architectures, by
using software engineering methodologies, refactoring, modeling, and modern development tools.
Prerequisite: TCSS 360.

### Course Overview

This course develops the skills and judgment to engineer software systems with modern
development tools. It rests on four connected areas: development workflows, tools, and practice;
software engineering and project management; system design and architecture; and re-engineering
existing systems. Students learn to decompose complex problems, choose and use tools well,
verify what tools produce, and make sound architectural decisions.

The quarter opens with three one-week individual builds that establish tools and workflow. From
week 4 on, students work in teams on a **capstone project**: a substantial software system built
for a real user. The capstone accumulates the theory and practice introduced each week. Teams
produce and use several design elements (system architecture, data design, user interface
design, and a test design) to deliver one final product.

## Learning Objectives

By the end of this course, students will be able to:

**Workflows, tools, and practice**

1. Select and configure development tools appropriate to a task or project
2. Manage context and project knowledge across tools, sessions, and collaborators
3. Verify and critically evaluate code and designs, whether written by people or generated by tools
4. Recognize when a tool is counterproductive and work effectively without it

**Software engineering and project management**

5. Decompose a complex problem into specified, testable subtasks
6. Plan, version, and document a team project with appropriate traceability
7. Manage a development workflow within a team, and communicate technical decisions to
   collaborators and stakeholders

**System design and architecture**

8. Design a software system's architecture from low-level components to high-level structure,
   and justify the design with models
9. Design the data, interface, and test strategy of a system and integrate them into one product
10. Evaluate design trade-offs, including cost, performance, reliability, and security

**Re-engineering and generative development**

11. Navigate, refactor, and extend large, unfamiliar or legacy codebases
12. Apply model-driven and automated approaches to code generation, such as domain-specific
    languages and code-generation tools, and reason about their limits

### Design Elective and ABET Student Outcomes

TCSS 461 is an approved design elective for the B.S. in Computer Science & Systems. The team
capstone is the course's major project: it integrates knowledge and skills from earlier course
work. The course contributes to these ABET student outcomes (Criteria for Accrediting Computing
Programs, 2026–2027):

- **Outcome 2:** design, implement, and evaluate a computing-based solution to meet a given set of
  computing requirements (the capstone and its design deliverables)
- **Outcome 5:** function effectively as a member or leader of a team (the team capstone)
- **Outcome 3:** communicate effectively in a variety of professional contexts (design review,
  final presentation)
- **Outcome 6:** apply computer science theory and software development fundamentals to produce
  computing-based solutions (objectives 8–12)

## Weekly Outline

| Week | Topic | Capstone milestone |
| --- | --- | --- |
| 1 | Modern development tools and workflows | Individual build 1 |
| 2 | Tool-assisted development: automation, context, and project knowledge | Individual build 2 |
| 3 | Systems with external and unreliable components: services, APIs, and models | Individual build 3; form teams and find a user |
| 4 | Requirements, specification, and decomposition; team process | **Proposal and requirements** |
| 5 | Distributed application architecture: client and server, shared state, databases, third-party APIs | **Architecture and data design** |
| 6 | User interface and experience design: usability heuristics | **UI/UX design** |
| 7 | Re-engineering: legacy code, refactoring, DSLs, model-driven and generative development | **Working prototype; design review** |
| 8 | Testing, verification, and code review | **Test plan and verification report** |
| 9 | Security and deployment | **Security review; deployed release** |
| 10 | Professional practice: ownership, attribution, and communicating technical work | **Final product, presentation, and retrospective** |

Each week also includes assigned reading and regular reflection on the work.

## The Capstone Project

- **Team-based**, running weeks 4–10 (seven of ten weeks)
- **Built for a real user** outside the team
- **Cumulative:** each week's topic feeds the matching milestone
- **Design deliverables:** requirements; system architecture, with models of its components and
  their interactions; data design; UI/UX design; test plan and verification report; security
  review
- **Final product:** a working, deployed system, a final presentation, and a team retrospective
- **Individual accountability** within each team, through reflections and peer evaluation
